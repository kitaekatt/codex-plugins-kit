# Delegation rules

Delegate by context footprint, not by how impressive the task sounds. Bulk
reading, noisy command output, independent research, repeated mechanical work,
and drafts that compress to a short conclusion are strong candidates.

A useful brief is executable without conversation. Include:

- goal and definition of done;
- exact paths and exclusive file ownership;
- constraints and prohibited actions;
- established premises with evidence;
- hypotheses that must be checked before mutation;
- checks to run; and
- a concise return structure covering changes, verification, unresolved risks,
  and any critical infrastructure created, moved, or removed.

Do not delegate and then redo the same work inline. If delegates disagree,
inspect the relevant evidence or commission a focused cross-check. A report
states intent; the diff and checks establish what happened.

Parallel writers must not share files. Repartition ownership before serializing
work unnecessarily. Use separate worktrees when units need independent mutable
repository state.
